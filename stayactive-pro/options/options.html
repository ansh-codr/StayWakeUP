How it works & Known limits

What StayActive Pro does

When you enable it for a site, the extension injects a script into the page's MAIN JavaScript world at document_start. This script overrides several browser APIs that websites use to detect tab visibility and focus:

  • document.hidden → always false
  • document.visibilityState → always "visible"
  • document.hasFocus() → always true
  • visibilitychange, blur events → silently blocked at capture phase (only when targeting window, document, or <html>)

Known limitations

  • Only fools JavaScript checks. Chrome's own background throttling (timers, network, rendering) is a browser-level decision and is not affected by this extension. Chrome may still throttle setTimeout and setInterval in hidden tabs; the "Silent audio" tool mitigates this partially.
  • Not all sites can be fixed. Sites that rely on server-side heartbeats, WebRTC state, or WebTransport will not be fooled.
  • Screen Wake Lock requires HTTPS. The Wake Lock API is only available on secure origins.
  • Extension pages. StayActive Pro cannot run on chrome://, chrome-extension://, or the Chrome Web Store.
  • Per-tab, not per-window. The icon/badge updates per-tab. If you have the same hostname in multiple tabs, each tab independently benefits from the injected script, but the popup shows the state for the active tab.

Privacy

StayActive Pro makes zero network requests and collects no data whatsoever. Everything stays local in chrome.storage.local.
